# The portable SQL core

This part of the book covers the **portable** half of the DSL — the half that does not depend on a specific engine: schema markers, projections, filters, ordering, grouping, window functions, joins, aliases, subqueries, CTEs, set operations, and DML.

The code every chapter is built on:

| Crate | What it defines |
|---|---|
| `rurqe-core` | the `SelectQuery`, `GroupedQuery`, `InsertQuery`, `UpdateQuery`, `DeleteQuery` builders, the typestates, `BuildError` |
| `rurqe-macros` | `select!`, `cols!`, `dto!`, `sql!`, `raw_sql!`, `#[derive(SqlType)]` |
| `rurqe` | the `select_from`, `insert_into`, `update`, `delete_from` entry points, the prelude, `pin_dialect_version!` |

Engine specifics (capability traits, versions, dialect extensions) are covered in separate parts of the book.

## Two entry-point forms

The facade publishes four generic functions (`crates/rurqe/src/lib.rs`):

| Call | Signature |
|---|---|
| `select_from::<D, T>()` | `pub fn select_from<D: Dialect, T: Table>() -> SelectQuery<D, T, (), NoProjection>` |
| `insert_into::<D, T>()` | `pub fn insert_into<D: Dialect, T: Table>() -> InsertQuery<D, T, (), ()>` |
| `update::<D, T>()` | `pub fn update<D: Dialect, T: Table>() -> UpdateQuery<D, T, Unfiltered, ()>` |
| `delete_from::<D, T>()` | `pub fn delete_from<D: Dialect, T: Table>() -> DeleteQuery<D, T, Unfiltered, ()>` |

A dialect prelude (`rurqe::postgres::prelude`, `rurqe::sqlite::sqlite3_35::prelude`, and so on) is generated by the `pin_dialect_version!` macro and pins the dialect, so the table is passed **by value**, without turbofish:

```rust
pub fn select_from<T: Table>(table: T) -> SelectQuery<$dialect, T, (), NoProjection>
pub fn insert_into<T: Table>(table: T) -> InsertQuery<$dialect, T, (), ()>
pub fn update<T: Table>(table: T) -> UpdateQuery<$dialect, T, Unfiltered, ()>
pub fn delete_from<T: Table>(table: T) -> DeleteQuery<$dialect, T, Unfiltered, ()>

pub type Error = $crate::core::query::ExecutionError<$error>;
pub type Result<T, E = Error> = ::core::result::Result<T, E>;

pub trait SelectFrom<T: Table, Positions>: Sized {
    type Row;
    fn from(self, table: T) -> SelectQuery<$dialect, T, Self::Row, HasProjection>;
}
```

Table markers are ZSTs, so the argument carries no data: `select_from(Users)` and `select_from(users)` are identical from the type's point of view; the difference is naming style only.

> **Compiler Guard in Action.** The dialect prelude re-exports the shared prelude first and the pinned entry points after it, so `use rurqe::postgres::pg16::prelude::*;` makes `select_from` the version that takes a table value and returns a `SelectQuery<Postgres<Pg16>, ...>`. Neither the dialect nor the version is mentioned in the query text anymore.

## What the entry points return

```rust
use rurqe::postgres::prelude::*;

let query = select_from(Users)          // SelectQuery<Postgres, Users, (), NoProjection>
    .select(cols!(UsersId, UsersName)); // SelectQuery<Postgres, Users, (i64, String), HasProjection>
```

A positional run of projections `cols!(UsersId, UsersName)` yields a positional tuple; `select!` yields named fields; `dto!` yields a named struct for decoding.

## The typestate map

The builders keep unreachable constructs out with **types**, not with runtime checks.

| Typestate | Declared in | What it forbids |
|---|---|---|
| `NoProjection` / `HasProjection` | `query/select/markers.rs` | `.build()` before `.select(...)` |
| `NoLock` / `Locked` / `LockWaitSet` | `query/select/markers.rs` | `nowait()` before `for_update()`; a repeated wait modifier |
| `LockUnavailable` | `query/select/markers.rs` | `FOR UPDATE` on `DISTINCT` / `DISTINCT ON` / `GROUP BY` |
| `SetOpApplied` / `TailClosed` | `query/select/markers.rs` | `.select(...)` after `UNION`; an operand after the combined-row ordering |
| `Unfiltered` / `Filtered` | `dml.rs` | `.build()` on a mutation without `WHERE` and without `.allow_all()` |
| `NoAssignments` / `HasAssignments` | `dml.rs` | `.build()` on an `UPDATE` without `SET` |
| `()` / `InsertSource` | `dml/insert.rs` | `.build()` on an `INSERT` without a row source |

Plus the separate `GroupedQuery` type (`query/group_by.rs`): after `.group_by(...)` the query stops being a `SelectQuery`, and the "a column is grouped or aggregated" rule is checked on every projection.
