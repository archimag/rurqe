# Ограничения без эмуляции

Принцип «native or nothing» означает: запрос либо рендерится в SQL, который
целевой движок исполняет нативно, либо для этого диалекта его не существует.
Ни одна отсутствующая возможность сервера не собирается на клиенте.

## Чего нет в SQLite

| Конструкция | Маркер | Почему |
|---|---|---|
| `LATERAL` joins | `SupportsLateralJoin` | в SQLite нет `LATERAL` |
| `FOR UPDATE` / `FOR SHARE`, `NOWAIT`, `SKIP LOCKED` | `SupportsRowLocking` | SQLite сериализует доступ блокировкой файла базы, построчных блокировок нет |
| `FULL OUTER JOIN` | `SupportsFullOuterJoin` | появился в 3.39.0, дальше всех объявленных маркеров |
| `DELETE … USING` | `SupportsDeleteUsing` | клаузы нет ни в одной версии |
| `DISTINCT ON (…)` | `SupportsDistinctOn` | расширение PostgreSQL |
| `GREATEST` / `LEAST` | `SupportsGreatest` | в движок не добавлены |
| `IS [NOT] DISTINCT FROM` | `SupportsDistinctFrom` | появился в 3.39.0, дальше всех объявленных маркеров |
| `ILIKE` | флаг `SUPPORTS_ILIKE` | у движка только регистрозависимый `LIKE`; предикат складывает операнды через `LOWER` |

## Как выглядит отказ

Отказ происходит в одном из двух мест:

1. **Компиляция.** Метод, который выпускает клаузу, ограничен маркером, поэтому
   для диалекта без возможности его нельзя даже назвать. Сообщение
   `#[diagnostic::on_unimplemented]` говорит на языке SQL, например
   «dialect `Sqlite<Sqlite3_35>` does not support row-level locking».
2. **`.build()`.** Правила, которым нужно сравнить клаузы между собой или
   утверждать *отсутствие* отношения в области видимости, проверяются
   детерминированно до сетевого ввода-вывода и возвращают типизированный
   `BuildError` — например, `DuplicateRelation` для двух отношений с одним
   эффективным именем.

## Чем это не является

Отсутствие возможности — не повод для замены:

* `MERGE` не собирается из `INSERT` + `UPDATE`;
* `FOR UPDATE` не эмулируется поверх блокировки базы;
* `FULL OUTER JOIN` не склеивается из двух внешних соединений;
* `LATERAL` не заменяется клиентским циклом запросов.

Если запрос нужен именно на SQLite, он выражается другим SQL, который
пишет разработчик; библиотека такой SQL не подставляет за него.
