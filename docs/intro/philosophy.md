# RURQE Philosophy

RURQE is a strictly typed SQL query builder, relational execution engine, and database-first code generation toolkit for Rust. Its central promise fits in one sentence: **a query that compiles is a valid statement for the target dialect and engine version**, and a query that is not valid does not compile.

## The problem

The gap between application code and a relational database has three familiar shapes:

1. **The schema lives in two places.** DDL describes one shape, application structs another, and the divergence surfaces at runtime (`column "..." does not exist`) instead of at build time.
2. **SQL is a string.** A string is not checked by the compiler: a typo in a column name, a reference to a table absent from `FROM`, a `LEFT JOIN` column read as a non-nullable value — each of them is a runtime error.
3. **Types are lost at the boundary.** Rows come back as anonymous tuples, and a `NULL` produced by an outer join arrives in a field declared as `f64`.

RURQE answers each of them with a language feature rather than with a convention: the compiler and the statement builder are the gates, and the database is never the first place an error is noticed.

## Ergonomics first

The dialect is pinned once by the prelude (`use rurqe::postgres::prelude::*;`), a table is passed by value (`select_from(User)`), and a column is a zero-sized value (`UserId`), so application code carries no type parameter at all. `select!` names the columns of a projection, `cols!` names the columns of a `.select(...)` argument, and the row that comes back is a struct with one field per projection — read as `row.user_name`, never as `row.0`. Completion and rename-refactoring work with no database connection, because the schema is encoded in types.

## Six principles

### 1. The schema is the single source of truth

The live catalog is introspected (`pg_catalog`, `information_schema`, the SQLite `PRAGMA` tables) instead of being rewritten by hand. The generated table and column markers, the DTO structs, and the snapshot `schema.lock` with its hash all come from it, so a name in Rust and a name in the database cannot drift apart unnoticed. This book holds itself to the same rule: every statement about a compiler guarantee or a runtime behaviour is backed by code that is compiled with the workspace.

### 2. No invalid statement reaches the database

A statement is checked twice. The compiler rejects every rule that can be stated as a positive assertion — a column of a relation the query never joins, a `LEFT JOIN` field read as `T`, an `UPDATE` without `WHERE`, a clause the pinned engine version does not support. Validation inside `.build()` then rejects the rules that need a negative assertion (two relations under one effective name) or that align one clause with a clause written later in the chain (`DISTINCT ON` against the leading `ORDER BY`), before any network I/O.

### 3. Native or nothing

A capability the engine cannot express is not emulated with a client-side workaround. `.for_update()` on SQLite is not "roughly the same thing": the method does not exist there, and the code does not compile. `RETURNING` below SQLite 3.35 is unavailable in exactly the same way.

### 4. Zero cost

The dialect is a zero-sized type parameter, table and column markers are zero-sized values, and rendering is a single pass over the recorded statement into a `String` plus a parameter vector. No virtual calls, no reflection, no garbage collector.

### 5. No panics

A failure is a value: an unsatisfiable statement is a `BuildError`, a failure of the engine is an `ExecutionError` that preserves the driver error, and a row that cannot be decoded is a typed decoding failure. Decoding never unwraps on data that came from outside the program.

### 6. KISS, YAGNI, DRY

No "just in case" fields and no dead code kept for later. Standard formats and cryptography use mature crates rather than hand-written parsers.

## What that gives in practice

| Promise | How it feels |
|---|---|
| A column typo is a compile error | the message names the column and the SQL clause, never a trait cascade |
| A `NULL` from a `LEFT JOIN` cannot be read as `f64` | `Option<T>` appears in the row type on its own |
| An `UPDATE` without `WHERE` cannot run by accident | the statement does not build until `.where_(...)` or a deliberate `.allow_all()` |
| A construct the engine lacks does not compile | on SQLite `.for_update()` is not a method at all |
| An ambiguous `JOIN` never reaches the database | the statement is refused, and the colliding relation is named |
| The schema never drifts from the code | `cargo db-codegen`, `schema.lock`, `cargo db-verify` |
